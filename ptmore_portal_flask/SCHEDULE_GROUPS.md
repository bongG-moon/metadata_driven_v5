# 사용자별 그룹 스케줄

Portal에서 한 번 등록하면 실행 대상 사번마다 기존 `portal_schedules` 설정 컬렉션에 문서가 하나씩 생성됩니다. 컬렉션 설정은 유지하며, 채널 선택을 지원하는 최신 Worker를 함께 배포해야 합니다.

- `_id`: 실행 문서의 고유 ID
- `group_id`: Portal에서 하나로 표시하는 그룹 ID
- `registrant_id`, `registrant_name`: 등록자와 수정 권한 기준
- `owner_id`: 기존 Worker가 GAIA 호출과 CUBE 수신에 사용하는 실행자 사번
- `owner_name`: 실행자 이름. 확인된 이름이 없으면 빈 값

예를 들어 10명을 선택하면 10회 GAIA 호출과 10개의 개인 DM이 발생합니다. 각 요청은 기존 Worker의 `CUBE_SCHEDULING` 플랫폼과 실행자별 세션 규칙을 따릅니다. 등록자는 대상 목록에서 제외할 수 있습니다. 실행자의 실제 GAIA 사용 권한은 외부 API에서 검증합니다.

Portal은 그룹별로 목록을 합치고 등록자 또는 관리자만 변경할 수 있도록 합니다. 실행 대상자라는 이유만으로 편집 권한을 주지 않습니다. 기존 단일 문서도 그대로 읽고, 수정 시 그룹 형식으로 전환합니다. 삭제는 해당 그룹의 실행 문서만 제거하며 Worker 실행 이력은 보존합니다.

그룹 변경 전 기존 문서를 비활성화해 실행 claim을 무효화합니다. 대상자별 문서를 갱신한 뒤 설정된 활성 상태를 반영합니다. 이 작업은 여러 MongoDB 문서에 걸친 순차 처리이며 트랜잭션은 아닙니다. 저장 실패 시 관련 문서를 비활성화하도록 시도하고 API 오류를 반환합니다. DB 자체가 중단되면 비활성화도 실패할 수 있으므로 복구 후 그룹 상태를 확인해야 합니다. 여러 관리자가 같은 그룹을 동시에 수정하는 작업은 피해주세요.

화면의 사용자별 상태는 각 문서의 최근 실행 결과입니다. 이전 실행의 상세 기록은 기존 실행 이력 컬렉션에 남습니다.

공통 사번 목록에 대해 `cube_enabled`, `mail_enabled`로 발송 채널을 선택합니다. 두 채널을 모두 켜도 사번별 GAIA 호출은 한 번이며 같은 답변을 전달합니다. 메일 주소는 Worker가 사내 H-API로 조회하며 등록자를 CC에 포함합니다. 기존 문서에 채널 설정이 없으면 CUBE만 사용합니다. 예전에 직접 입력한 `email_recipients`는 자동 발송하지 않습니다. 사번으로 다시 등록하고 메일을 켜 주세요.

배포 설정과 주의 사항은 `../gaia_cube_server/scheduler_worker_server/MAIL_DELIVERY.md`를 참고하세요.
