# Data Analysis Flow 누적 변경 검증 질문셋

기준일: 2026-07-29
권장 모델: `gemini-3.5-flash-lite`

## 1. 핵심 단일 질문

각 질문은 새로운 세션에서 실행한다.

### 1-1. Source별 조건 분리와 결과 의미

1. `6/24일 투입 실적 대비 D/S1, DA1공정에서 WIP 많은 제품 알려줘`
   - 생산 실적은 `INPUT`만, WIP는 `D/S1`, `D/A1`만 적용되는지 확인
   - WIP 내림차순으로 전체 결과가 정렬되는지 확인
   - 질문에 없는 비율 계산이나 임의 Top N이 추가되지 않는지 확인
   - 답변과 결과 컬럼에서 INPUT 실적과 대상 공정 WIP가 구분되는지 확인

2. `오늘 현시간 기준 INPUT실적은 있으나 D/A공정 WIP 없는 제품 확인해줘`
   - `production_today`에는 `INPUT`만 적용되는지 확인
   - `wip_today`에는 `D/A1~D/A6`만 적용되는지 확인
   - 두 source 모두에 `INPUT + D/A1~D/A6` 통합 목록을 적용하지 않는지 확인
   - 결과가 `INPUT_QTY > 0`, `DA_WIP_QTY = 0`인 제품인지 확인
   - 답변이 일반적인 공정별 생산량 요약으로 잘못 생성되지 않는지 확인

3. `FCB 공정 생산 실적과 W/B2 공정 재공수량을 제품별로 비교해줘`
   - 생산 실적 source의 FCB가 `FCB1`, `FCB2`, `FCB/H`로 확장되는지 확인
   - WIP source의 `W/B2`는 단일 공정으로 유지되는지 확인
   - 두 source의 공정 조건을 합쳐서 동일하게 적용하지 않는지 확인

### 1-2. 숫자 필터와 공정 범위

4. `W/B공정 IN TAT 10시간이상 된 LOT 알려줘`
   - `IN_TAT ge 10`이 숫자 비교로 실행되는지 확인
   - `unsupported_filter_operator: ge` 오류가 발생하지 않는지 확인
   - 결과에 `LOT_ID`, `OPER_NAME`, `IN_TAT`가 포함되는지 확인

5. `D/S1~D/A4 공정 Hold 된 Lot ID 알려줘`
   - `filter_ordered_range`가 선택되는지 확인
   - HOLD 필터보다 공정 범위 helper가 먼저 실행되는지 확인
   - 양 끝 공정만 조회하지 않고 `OPER_SEQ` 기준 중간 공정까지 포함하는지 확인

6. `7월 1일 D/A1~W/B6 공정 구간의 공정별 생산량을 OPER_SEQ 순서로 알려줘`
   - `OPER_SEQ`를 숫자로 변환하여 범위를 계산하는지 확인
   - `D/A1`부터 `W/B6`까지 양 끝을 포함하는지 확인
   - 최종 결과가 `OPER_SEQ` 순서로 정렬되는지 확인

### 1-3. 공정·공정 그룹 인식

7. `DA, WB공정 HOLD LOT 알려줘`
   - DA와 WB 두 그룹이 모두 인식되는지 확인
   - `D/A1~D/A6`, `W/B1~W/B6`이 모두 필터에 포함되는지 확인

8. `WB & DA 공정 Hold Lot LIST알려줘`
   - 순서와 구분자가 달라도 WB와 DA 두 그룹이 모두 인식되는지 확인

9. `D/S1&D/A 공정 Hold Lot LIST알려줘`
   - `D/S1`은 단일 공정으로 유지되는지 확인
   - D/A는 `D/A1~D/A6` 그룹으로 확장되는지 확인

10. `7월 5일 FCB1,FCB2,FCB/H 공정 실적 알려줘`
    - 세 공정이 누락 없이 하나의 `OPER_NAME in` 조건에 포함되는지 확인

### 1-4. 제품 조건과 빈 값

11. `HBM제품 WB공정에서 아침재공 수량 알려줘`
    - WB가 `W/B1~W/B6`으로 확장되는지 확인
    - `TSV_DIE_TYP not_blank` 조건이 pandas 전처리 코드에도 포함되는지 확인
    - HBM 조건이 의도 분석에만 남고 실행 코드에서 누락되지 않는지 확인

12. `오늘 WBM 공정의 제품별 생산량을 알려줘. 제품 정보가 비어 있는 행도 제외하지 말고, 비어 있는 제품 정보는 빈칸으로, 생산량이 비어 있으면 0으로 보여줘.`
    - WBM을 WB 그룹이 아니라 단일 `W/BM` 공정으로 인식하는지 확인
    - null·공백 제품 차원 행이 결과에서 제거되지 않는지 확인
    - null·공백 차원은 `""`, null 생산량은 `0`으로 표시되는지 확인

13. `현재 제품 중 TECH, DEN, PKG_TYPE2, MCP_NO는 같지만 MODE, PKG_TYPE1 또는 LEAD가 다른 제품들을 찾아서 보여줘.`
    - 동일 기준과 비교 기준을 구분하는 비교 코드가 생성되는지 확인
    - 단순 groupby 결과만 반환하지 않는지 확인
    - `unsafe_code`, `missing_code` 오류 없이 최초 실행에 성공하는지 확인

### 1-5. UPH와 기본 표시 컬럼

14. `FCB2공정 제품별 UPH 알려줘`
    - UPH를 합산하지 않는지 확인
    - 추가 집계가 필요하면 `mean`을 사용하는지 확인
    - 제품 결과에 `EQUIP_MODEL`, `RECIPE_ID`, `OPER_NAME`, `UPH`가 유지되는지 확인

15. `WB공정 L-217제품 차수별, 장비 기종별 UPH 알려줘`
    - `OPER_NAME`, `EQUIP_MODEL` 그룹별 UPH 평균인지 확인
    - UPH 합계가 출력되지 않는지 확인

16. `F315 L-116로 시작하는 제품 WB 공정 차수별 UPH 알려줘`
    - `MCP_NO starts_with L-116` 조건이 적용되는지 확인
    - 차수별 UPH가 `mean`으로 계산되는지 확인

17. `현재 D/A1 공정의 장비 모델, Recipe, 공정, UPH를 보여줘`
    - 별도 grouping 요청이 없으므로 원본 상세 UPH를 유지하는지 확인
    - 기본 상세 컬럼 `EQUIP_MODEL`, `RECIPE_ID`, `OPER_NAME`과 `UPH`가 표시되는지 확인

18. `현재 D/A1 공정에 배정된 장비를 장비 모델과 Recipe 조합별로 보여줘`
    - UPH를 명시하지 않았으므로 불필요하게 `eqp_uph`를 선택하지 않는지 확인
    - `equipment_assign`에서 장비 ID, 장비 모델, Recipe가 표시되는지 확인

## 2. 핵심 멀티턴 질문

각 시나리오는 새로운 `session_id`로 시작하고, 시나리오 안의 질문은 같은 세션에서 순서대로 실행한다.

### MT-1. 제품별 장비 조회와 독립 질문 전환

1. `오늘 DA공정에서 생산량 상위 3개 제품을 알려줘.`
2. `이 제품들에 할당된 현재 장비 대수와 장비 LIST를 제품별로 알려줘.`
3. `그중 장비 대수가 가장 많은 제품만 보여줘.`
4. `오늘 WB공정에서 생산량 상위 5개 제품을 알려줘.`

확인 항목:

- 2번은 신규 `equipment_assign` 조회가 있는 `followup_requery`인지 확인
- 직전 결과의 표준 제품 grain 전체를 매칭 키로 사용하는지 확인
- 각 이전 행은 AND, 여러 이전 행은 OR로 매칭되는지 확인
- `null`, `NaN`, `<NA>`, 빈 문자열, 공백 제품 키가 모두 `""`로 정규화되는지 확인
- 장비 대수는 제품별 `EQP_ID nunique`, 장비 LIST는 제품별 고유 목록인지 확인
- 장비가 없는 이전 제품도 제거하지 않고 장비 대수 0으로 유지하는지 확인
- 3번은 신규 조회 없이 이전 결과만 정렬하여 1개를 남기는지 확인
- 4번은 이전 결과를 참조하지 않는 완전한 `new_analysis`인지 확인

### MT-2. HOLD LOT에서 이력 조회

1. `W/B공정 현재 HOLD LOT와 HOLD사유 알려줘`
2. `HOLD 시간이 가장 오래된 LOT의 이력을 보여줘`

확인 항목:

- 2번에서 `hold_history`가 선택되는지 확인
- 직전 결과의 `LOT_ID`가 `required_params.LOT_ID`로 전달되는지 확인
- `catalog 필수 파라미터 값이 없습니다: LOT_ID` 오류가 발생하지 않는지 확인
- HOLD 시각 오름차순 정렬 후 가장 오래된 1건을 반환하는지 확인

### MT-3. 이전 source 재그룹과 공정 조건 유지

1. `W/B공정 차수별 생산량과 재공수량 알려줘`
2. `위 결과를 제품별로 보여줘, 공정 조건도 유지해줘`

확인 항목:

- 2번이 이전 최종 표만 재분석하는지, 이전 source를 재사용하는지 LLM이 질문 의도에 맞게 선택하는지 확인
- 제품별 재그룹에 필요한 원본 source가 유지되는지 확인
- 두 source의 `W/B1~W/B6` 조건이 유지되는지 확인
- 불필요한 신규 외부 조회가 발생하지 않는지 확인

### MT-4. 제품 조건만 변경

1. `어제 Mobile제품의 PKG OUT실적을 제품별로 알려줘`
2. `pop제품은어땠어?`

확인 항목:

- 날짜, `PKG OUT`, 제품별 grain은 유지되는지 확인
- Mobile 조건만 POP 조건으로 교체되는지 확인
- 이전 Mobile 결과 행 자체를 POP 제품 조건으로 사용하지 않는지 확인

### MT-5. 이전 결과만 다시 분석

1. `오늘 DA공정에서 생산량 상위 5개 제품을 알려줘`
2. `그중 생산량이 가장 많은 제품만 보여줘`

확인 항목:

- 2번은 `previous_result_transform`인지 확인
- 신규 production 조회가 발생하지 않는지 확인
- 이전 5개 결과 안에서 생산량 최대 1개만 남기는지 확인
