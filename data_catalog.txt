## 기본 상세 표시 metadata 입력 기준

각 dataset 블록에는 필요할 때 아래 필드를 직접 지정하거나 수정할 수 있어.
default_detail_columns는 사용자가 출력 컬럼을 따로 말하지 않은 detail 또는 entity_list 질문에서 기본으로 유지할 컬럼이야.
값을 바꿀 때는 해당 dataset 블록에 "default_detail_columns는 A, B로 바꿔줘"처럼 원하는 전체 목록을 적어. 원문에 없는 컬럼은 추측해서 추가하지 마.
dataset 간 join 기준과 실행 순서는 Table Catalog에 넣지 말고 Domain의 analysis_recipes에 등록해.

Target2 Goodocs Plan

text
PKG 계획 데이터의 dataset_key는 반드시 target으로 등록해줘. 표시명이나 데이터 설명에서 다른 dataset_key를 새로 만들지 마.
화면에 보일 이름은 PKG Target Goodocs Plan이면 돼.
Goodocs PKG 계획 문서에서 일자와 제품 속성별 INPUT계획, OUT계획을 가져오는 데이터야.
이 데이터는 Goodocs source이고 별도 필수 조회 파라미터는 없어.
이게 중요한데 이 데이터에서 사용하는 DATE형식은 'YYYYMMDD'가 아니라 'YYYY-MM-DD'형식이라서 형식 변환이 필요해
계획 수량은 'INPUT 계획'과 'OUT 계획' 두 컬럼에 있는 값을 모두 사용해. 두 컬럼 모두 분석 수량으로 쓰는 계획 수량 컬럼이야.
두 계획 수량 컬럼의 원본 값은 K 단위로 1000이 생략되어 있어. 문자열 값도 숫자로 변환한 뒤 1000을 곱하고, 이 변환은 집계·join·계획 대비 실적 비교 전에 한 번만 적용해. 계획만 조회할 때도 변환된 실제 수량 단위로 보여줘.
Goodocs 문서 ID는 1212121212121212121212 이야
목표2 문서에는 DATE, Mode, DEN, TECH, PKG1, PKG2, LEAD, ORG, MCP NO, INPUT 계획, OUT 계획 컬럼이 있어.

filter_mappings는 DATE -> DATE, MODE -> Mode, DEN -> DEN, TECH -> TECH, ORG -> ORG, PKG_TYPE1 -> PKG1, PKG_TYPE2 -> PKG2, LEAD -> LEAD, MCP_NO -> MCP NO, INPUT_PLAN_QTY -> INPUT 계획, OUT_PLAN_QTY -> OUT 계획으로 연결해줘.



Equipment Status

text
장비 Assign 현황 데이터는 equipment_assign으로 등록해줘.
이 데이터는 Oracle기반 조회고 db_key는 PNT_RPT야
화면에 보일 이름은 Equipment Assign현황 이면 돼.
Oracle PNT_RPT의 EQP_TABLE에서 설비별 보유 현황을 가져오는 데이터야.
이 데이터는 필수 파라미터 없이 조회해.
주요 수량 정보는 없고 
장비 수를 물어볼때는 이 데이터의 EQUIP_ID(표준컬럼 EQP_ID) 컬럼값의 중복 제거된 ROW COUNT가 장비 대수야. 따로 장비대수 컬럼은 없고 계산해줘야해.

query_template:

SELECT

  EQUIP_MODEL, 
  PRESS_CNT,
  OPER,
  OPER_NM,
  MODE, 
  DENSITY, 
  TECH, 
  PKG1, 
  PKG2, 
  LEAD, 
  ORG,
  PKGSIZE,  
  MCP_NO,
  DEVICE,
  DEVICE_DESC,
  LOT_ID,
  RECIPE_ID
FROM  EQP_TABLE
WHERE 1=1 

filter_mappings는 EQP_ID -> EQUIP_ID, EQP_MODEL -> EQUIP_MODEL, MODE -> MODE, DEN -> DENSITY, TECH -> TECH, PKG_TYPE1 -> PKG1, PKG_TYPE2 -> PKG2, LEAD -> LEAD, MCP_NO -> MCP_NO, ORG -> ORG, DEVICE -> DEVICE, DEVICE_DESC -> DEVICE_DESC, OPER_NUM -> OPER, OPER_NAME -> OPER_NM, LOT_ID -> LOT_ID, RECIPE_ID -> RECIPE_ID 로 연결해줘.
default_detail_columns는 표준 컬럼 EQP_ID로 저장해줘.
조회 원본의 EQUIP_MODEL은 표준 컬럼 EQP_MODEL로 정규화하고, pandas 계획과 결과 계약에서는 EQP_MODEL만 사용해.


Equipment Recipe UPH

text
장비모델/제품별 UPH 데이터는 eqp_uph로 등록해줘.
이 데이터는 Oracle기반 조회고 db_key는 GMS_DB야
화면에 보일 이름은 Equipment UPH이면 돼.
Oracle GMS_DB의 UPH 테이블에서 장비모델/공정/제품의 평균 UPH를 가져오는 데이터야.
이 데이터는 필수 파라미터 없이 조회해.
제품/장비모델별 UPH 값은 UPH 컬럼에 나와있어.

query_template:

SELECT 

  EQUIP_MODEL
  ,OPER
  ,OPER_NAME
  ,PRESS_CNT
  ,PROD_TYP AS "MODE"
  ,TECH
  ,ORG
  ,DENSITY
  ,PKG_TYP AS PKG1
  ,PKG_TYP_2 AS PKG2
  ,LEAD_CNT AS LEAD
  ,MCP_NO
  ,RECIPE_ID 
  ,round(AVG_UPH_VAL,2) AS UPH
  ,WORK_DT AS LOAD_DT
  ,BASE_DT
FROM UPH
WHERE 1=1

filter_mappings는 EQP_MODEL -> EQUIP_MODEL, OPER_NAME -> OPER_NAME, OPER_NUM -> OPER, MODE -> MODE, TECH -> TECH, ORG -> ORG, DEN -> DENSITY, PKG_TYPE1 -> PKG1, PKG_TYPE2 -> PKG2, LEAD -> LEAD, MCP_NO -> MCP_NO, RECIPE_ID -> RECIPE_ID로 연결해줘.
columns에는 SQL 조회 결과에 실제로 반환되는 이름인 EQUIP_MODEL, OPER, OPER_NAME, PRESS_CNT, MODE, TECH, ORG, DENSITY, PKG1, PKG2, LEAD, MCP_NO, RECIPE_ID, UPH, LOAD_DT, BASE_DT를 저장해줘. AS 앞의 원본명 PROD_TYP, PKG_TYP, PKG_TYP_2, LEAD_CNT, AVG_UPH_VAL, WORK_DT를 조회 결과 컬럼으로 저장하지 마.
조회 원본의 EQUIP_MODEL은 표준 컬럼 EQP_MODEL로 정규화하고, pandas 계획과 결과 계약에서는 EQP_MODEL만 사용해.
default_detail_columns는 EQP_MODEL, RECIPE_ID, OPER_NAME으로 저장해줘.
다른조건이 없을 때 기본적으로 보여줄 표준 컬럼은 EQP_MODEL, RECIPE_ID, OPER_NAME이야.
UPH는 사용자가 UPH를 물었을 때 metric 컬럼으로 추가하고, PRESS_CNT와 MCP_NO는 사용자가 질문에서 요구할 때만 출력 컬럼으로 선택해.
metric_semantics의 UPH는 semantic_type이 average이고 additive는 false야. source_already_aggregated는 true이고 default_rollup과 allowed_rollups는 mean만 사용해. 제품별 UPH처럼 추가 grouping이 없으면 장비 모델, Recipe, 공정별 원본 UPH를 유지하고, 사용자가 차수별·장비 기종별처럼 grouping을 명시한 경우에만 그 그룹별 평균을 계산해. UPH를 sum으로 합산하면 안 돼.


LOT Status

text
LOT 정보조회 데이터는 lot_status로 등록해줘.
화면에 보일 이름은 LOT Status이면 돼.
현재 재공에서 작업중 Lot 수량, 작업대기 Lot 수량, Hold Lot 수량, Lot별 TAT를 확인하는 Oracle 데이터야.
이 데이터는 필수 조회 조건이 없어. (LOAD_DT와 BASE_DT는 단순 확인용 값)
수량/지표로는 PROD_QTY, WF_QTY, IN_TAT, CUM_TAT를 사용해.
특정 LOT들을 물어볼때는 LOT_ID컬럼에 IN조건을 걸면 돼
Lot 건수는 LOT_ID를 count해야하고,
DIE수량이나 UNIT수량을 물어볼때는 PROD_QTY값의 합을 구해야해.
그리고 Wafer수량, 웨이퍼수량을 물어볼때 사용하는게 WF_QTY컬럼이야.

IN_TAT는 현재 공정 유입 이후 TAT이고 CUM_TAT는 누적 TAT야.
HOLD여부는 HOLD_STAT컬럼이 'OnHold'값을 가지는 경우를 말해(OnHold, NotOnHold)

source는 oracle이고 db_key는 PNT_RPT야.

/*Current Wip Status*/
SELECT
ERM_ID,OPER,OPER_NAME,FAB,OWNER,GRADE,DEVICE,LOT_ID,SUB_LOT_ID,PROD_QTY,WF_QTY,IN_TAT,CUM_TAT,EQP_ID,FLOW_ID,OPER_IN_TM,FAC_IN_TIME,HOLD_STAT,HOLD_REASON,FAMILY,MODE,DENSITY,TECH,ORG,PKG1,PKG2,PKG3,LEAD,MCP_NO,THK_CD,LOT_STAT,LOT_GRP,PKG_SIZE,HOT_LOT,HOT_LEVEL,PKG_COMPOSIT,DURABLE_ID,DURABLE_TYP,SUB_QTY,TSV_DIE_TYPE,EVENT_DESC,MOVE_IN_TM,PAD_ABNORMAL,SWR_REQ_NO,INSP_TARGET
FROM WIP_STATE
WHERE 1=1

filter_mappings는 OPER_NAME -> OPER_NAME, OPER_NUM -> OPER, MODE -> MODE, DEN -> DENSITY, TECH -> TECH, ORG -> ORG, PKG_TYPE1 -> PKG1, PKG_TYPE2 -> PKG2, LEAD -> LEAD, MCP_NO -> MCP_NO, TSV_DIE_TYP -> TSV_DIE_TYPE, EQP_ID -> EQP_ID, LOT_ID -> LOT_ID로 연결해줘.
default_detail_columns는 LOT_ID, OPER_NAME, PROD_QTY, WF_QTY, IN_TAT, CUM_TAT, HOLD_STAT, HOLD_REASON, LOT_STAT로 저장해줘.

HOLD History

text
HOLD 이력 조회 데이터는 hold_history로 등록해줘.
화면에 보일 이름은 HOLD History이면 돼.
이 데이터는 Oracle기반 조회고 db_key는 PNT_RPT야.
HOLD된 LOT의 HOLD 발생 사유, HOLD 발생 시각, 해제 예정일, HOLD 설명을 확인하는 Oracle 데이터야.
LOT_ID가 조회 필수 조건이야.
HOLD Lot 건수는 LOT_ID의 UNIQUE수량를 count해야하고,
HOLD DIE수량이나 UNIT수량을 물어볼때는 OLD_SUB_PROD_QTY값의 합을 구해야해.
HOLD_TM은 HOLD 발생 시각이고 HOLD_CD는 HOLD CODE를 말하는거야
HOLD DESC는 상세 사유를 담은 컬럼이야

default_detail_columns는 LOT_ID, OPER_NAME, HOLD_TM, HOLD_CD, HOLD_DESC로 저장해줘.
이 데이터는 사용자가 LOT 번호를 직접 말하면 그 LOT의 이력을 바로 조회할 수 있어. 같은 세션에서 바로 앞에 조회한 LOT 목록이 있으면, 그 LOT 번호들을 사용해 이력도 이어서 조회할 수도 있게 해줘. 한 번에는 최대 200개의 LOT만 조회하면 돼.
